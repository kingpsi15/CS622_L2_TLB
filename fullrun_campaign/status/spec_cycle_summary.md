# Full-run campaign: SPEC CPU2017 cycle comparison (5 designs)

Summary produced by Sahil's analysis of the full-run campaign (timing CPU after atomic boot,
one benchmark per guest). Numbers copied as sent. Spot-checked against raw `stats.txt`
(`board.processor.switch.core.numCycles`) for 605.mcf_s and 507.cactuBSSN_r on all five
designs: exact match.

Corrections to the labels in the original summary:
- `agile` is the Agile/NaiveFP **prefetcher** design (NINE plus page-table-neighbour prefetching),
  not an insertion/bypass policy. In these runs `pfIssued = 0`, i.e. the prefetcher issued no prefetches.
- `perf` is **Perforated Pages as built**, not an ideal/upper-bound TLB. Its L2 stores a separate
  physical address per 4KB page (about 512x the reach of the other designs); see report Section
  "A Second Look at Perforated Pages".
- The original header said 0 GAPBS / 0 KV workloads; the GAPBS and key-value suites were run
  separately (see `results_final/fullrun_suites.csv`).
- Cycles cover the whole guest run after boot, so they include SPEC's own setup and output check.
